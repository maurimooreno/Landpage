# Producto

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro con TypeScript estricto, Tailwind CSS y salida estática. JavaScript de cliente únicamente para
la interacción mínima del formulario de contacto.

## Users

Responsables de pequeñas y medianas empresas de Argentina, o personas con capacidad de evaluar y
encargar software, que necesitan mejorar un proceso mediante aplicaciones internas, APIs,
integraciones, automatizaciones o software empresarial a medida.

## Product Purpose

Explicar con rapidez qué problemas puede resolver un desarrollador independiente, aportar evidencia
suficiente para generar confianza y convertir visitas relevantes en solicitudes de contacto
cualificadas. La acción principal es solicitar que la empresa devuelva el contacto por llamada,
WhatsApp o correo dentro de un día hábil.

## Positioning

Un interlocutor técnico directo que entiende el proceso empresarial antes de proponer software y
construye soluciones a medida sin la fricción de una estructura de agencia.

## Operating Context

La evaluación sucede principalmente desde una landing pública en español. El visitante recorre la
propuesta, los problemas abordados, la experiencia, los casos demostrativos y un formulario mínimo.
La prestación se comunica como remota para Argentina.

## Capabilities and Constraints

- El MVP publicable incluye propuesta, servicios, experiencia, proyectos, contacto, privacidad y
  confirmación.
- El formulario solicita únicamente nombre, vía preferida y el teléfono o correo correspondiente,
  más consentimiento; no solicita una descripción del proyecto.
- El formulario debe quedar desacoplado de un proveedor concreto y conservar un enlace directo de
  correo como alternativa.
- El sitio busca WCAG 2.2 AA, navegación por teclado, uso táctil, responsive mobile-first, SEO técnico,
  Core Web Vitals de laboratorio y JavaScript mínimo.
- No se implementan analítica, RUM ni recopilación adicional de datos personales.
- Los datos comerciales actuales son demostrativos y no pueden interpretarse como afirmaciones reales.

## Brand Commitments

- Voz: directa, profesional, clara y sin exageraciones comerciales.
- Evitar apariencia genérica de plantilla, exceso de tarjetas, gradientes decorativos y promesas vagas.
- Identidad temporal autorizada por el propietario: **Taller Norte — Software a medida**.
- Ubicación temporal: Argentina, atención remota.
- Correo temporal: `hola@tallernorte.example`.
- Todo dato temporal debe estar identificado como demostrativo y reemplazarse antes de un lanzamiento real.

## Evidence on Hand

No se entregaron todavía identidad legal, correo operativo, trayectoria verificable, clientes,
testimonios, métricas, imágenes ni proyectos autorizados. El propietario autorizó usar datos ficticios
para construir y probar la interfaz.

Inventario de demostración autorizado:

- Perfil profesional: desarrollador independiente orientado a software empresarial; dato ficticio.
- Experiencia: capacidades y tecnologías ilustrativas, sin años ni cifras atribuibles; dato ficticio.
- Casos: hasta tres casos sintéticos, rotulados **Caso demostrativo**, sin marcas de terceros.
- Resultados: únicamente resultados cualitativos hipotéticos, rotulados como tales.
- Assets: recursos originales del proyecto o composiciones abstractas; sin logos ni material de clientes.
- Claims prohibidos: clientes reales, antigüedad, tamaño de equipo, certificaciones, ingresos, porcentajes,
  testimonios o resultados cuantitativos no aportados.

**Bloqueo de publicación:** antes de desplegar como sitio comercial deben sustituirse el nombre, correo,
responsable de privacidad y toda evidencia demostrativa por información real aprobada por el propietario.

## Product Principles

1. Comprender antes de vender: conectar cada capacidad técnica con un problema operativo concreto.
2. Prueba honesta: distinguir siempre demostraciones de experiencia verificable.
3. Contacto sin fricción: pedir el mínimo de datos y explicar qué ocurrirá después.
4. Ingeniería proporcional: preferir soluciones estáticas, rápidas, seguras y mantenibles.
5. Confianza mediante precisión: usar lenguaje específico, estados claros y compromisos verificables.

## Accessibility & Inclusion

WCAG 2.2 nivel AA como objetivo. La experiencia debe funcionar con teclado, lectores de pantalla,
touch, zoom, movimiento reducido y orientaciones móviles aplicables, en landing, privacidad y
confirmación.
