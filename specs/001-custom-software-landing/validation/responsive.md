# Responsive, touch and orientation evidence

## Automated matrix

- Routes: landing, privacy, and contact confirmation.
- Widths: 320, 390, 768, 1024, and 1440 CSS px.
- Relevant states: mobile navigation open, contact channel switch, validation/failure state,
  privacy return link, and neutral confirmation state.
- Touch: exercised with Playwright mobile projects using `hasTouch`, not mouse emulation.
- Orientations: portrait 390×844 and landscape 844×390 are applicable to all three web routes and
  are tested. No orientation is excluded.
- Reflow: 320 CSS px represents the WCAG 400% reflow condition for a 1280 px viewport.

Evidence is generated by `landing-responsive.spec.ts`, `cross-cutting.spec.ts`, and the mobile
Playwright projects.

Final local result: 32/32 responsive and touch checks passed serially across mobile Chrome and mobile
Safari. The shared Chromium suite passed 53 tests with the touch-only desktop case correctly skipped.
Portrait and landscape interaction succeeded on landing, privacy, and confirmation; no orientation
was excluded.

The WebKit functional matrix passed 44 applicable tests (10 Chromium-only axe checks skipped). The
local Windows Firefox binary did not begin its first test and was stopped after repeated no-output
intervals; the SHA-pinned Linux CI matrix remains the required Firefox evidence.
